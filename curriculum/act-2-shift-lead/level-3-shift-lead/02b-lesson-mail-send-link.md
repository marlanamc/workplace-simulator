# Lesson 2: Send the Link, Not a Copy

**Time:** ~4 minutes · **Level:** 5 — Shared Files · **Track:** Shared Files
**Task key:** `mail-send-link` · **Status:** built — Mail opens straight to a
compose window addressed to Jordan; the learner writes one or two lines that
point at the shared file.
**Prerequisite:** Lesson 1 (`files`) complete — the file is already shared

## We will learn...
- tell a coworker where a file is by sending the **link**, not by attaching a
  copy. A link always points at the current file; an attached copy stops
  matching the moment you edit the original.

## Simulator practice (~4 min)
1. After finishing Lesson 1, the desktop hands you Mail. It opens straight to a
   new message to **Jordan Kim**, subject already filled in.
2. Write one or two short lines: say it's this week's schedule, and that the
   link is here. Sentence starters are available if you want them.
3. Do **not** write "attached" or attach a copy — you already shared the file,
   so Jordan can open it from the link. Saying "attached" gets a friendly
   reminder.
4. Send. Jordan replies that the link opened fine.

## Notes for next time
- The whole skill is the reason, not the mechanic: a link stays current, a
  copy goes stale. Name a time this bit someone — a schedule, a price list, a
  form everyone had a different version of.
- This mirrors Lesson 1 from the other side: there the learner *granted* view
  access; here they *use* that share by pointing someone at it.
